This release introduces the ` gol update` command for applying changes to a GOL from `.osc` files or via a replication server.

This capability is currently **experimental** and may undergo significant changes in its implementation.

Current limitations:

- The GOL is locked for writing during updates; this limitation will be lifted with the storage engine upgrade in v3.0, which supports true multi-reader/single-writer concurrency

- Updates for very long periods on large datasets may run out of memory. Upcoming releases will automatically divide large updates in multiple stages if memory is tight

## New functionality

- `gol update`: Update a GOL from OSC files or a replication server
